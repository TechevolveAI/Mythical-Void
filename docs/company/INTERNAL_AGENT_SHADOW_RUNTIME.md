# Mythical Internal Agent Shadow Runtime

**Status:** Local single-process rehearsal; not a promoted agent runtime  
**Date:** 11 August 2026  
**Control:** A-030 internal operating-cycle assurance

## Outcome

A-030 executes one bounded company operating rehearsal across objective
selection, responsibility assurance, delegation planning, Kevin's decision
interface, and adult-research readiness. It proves that the registered controls
can run together, produces content digests and compact results, and checks that
the company repository did not change while they ran.

This is more than a diagram, but less than an autonomous multi-agent runtime.
Every step currently runs in one local process under one operator identity.
The named agent IDs express responsibility and independent-review design; they
do not prove isolated identities or independent human judgment.

## Operating cycle

The machine-readable contract is
[`automation/shadow-runtime.json`](automation/shadow-runtime.json). One dry
run executes:

1. AG-001 compiles governed objectives and actions with A-014.
2. AG-010 verifies agent/function/workflow coverage with A-023; AG-001 is the
   separate designed evaluator because AG-010 owns that control.
3. AG-001 builds the A-024 work-order plan from explicitly ready work only.
4. AG-001 compiles the bounded A-025 Kevin decision queue.
5. AG-005 checks A-029 adult-research readiness, with AG-010 as evaluator.

Each command must exactly match its registered workflow implementation, accept
only exit 0 or a healthy gated exit 2, return parseable JSON identifying the
expected workflow, expose no true external-authority flag, and leave the
company files byte-for-byte unchanged.

## Authority boundary

A-030 cannot dispatch work, invoke a generative agent, write a cycle record,
change an objective, close an action, use credentials, read restricted data,
contact anyone, publish, deploy, collect, spend, or approve anything. It has no
scheduler, protected memory/history, alert route, approval verifier, service
identity, or external executor.

The rehearsal output is not an approval token. Conversation about it is not
authorization.

## Evidence record

The default command prints one non-persistent JSON record containing:

- contract and step-output SHA-256 digests;
- expected and observed workflow IDs;
- exit state and failure counts;
- repository mutation count;
- designed producer/evaluator separation;
- explicit statements that runtime identity separation is unproven, nothing
  was persisted, and no external action was authorized.

Raw step output is not copied into the record. No shared customer, support,
credential, or financial payload is permitted.

## Promotion

This rehearsal does **not** count toward the four eligible shadow cycles in
OA-038. Eligibility first requires:

- Kevin's confirmation of the operating cell, accountable owner, backup, and
  urgent exception recipient;
- isolated service identities for orchestration and assurance;
- protected minimal history, authenticated alerts, retention, backup, restore,
  access review, and cost limits;
- bounded scheduling plus tested kill switch, replay, failure, and recovery;
- comparison with a human routing decision and independent approval of cycle
  accuracy;
- no expansion of external authority.

Only then may four eligible cycles be recorded and reviewed. External actions
remain governed separately regardless of internal-runtime promotion.
